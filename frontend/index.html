Honest extrapolation

Extrapolated sections are marked, never hidden. Solid where the datasheet speaks, dashed amber where it does not. Every point on a curve carries a confidence score. How it works

  • Solid line, 100 % confidence. Computed by the model inside the datasheet’s C-rate and temperature range, where its parameters apply.
  • Dotted line, confidence drops. Flagged when the C-rate exceeds the datasheet maximum, the temperature leaves the datasheet range, or state of health falls below 95 % (datasheets describe a fresh cell).
  • Shaded band. The voltage uncertainty grows with every lost percent of confidence, so you see how far to trust the number. Each cell also reports its minimum confidence.

The story in one page

openBatteryFlux turns a cell’s datasheet envelope into a model you can simulate, compare, calibrate, validate and export. This page follows that story in order: the cell, the model, how it behaves, how far to trust it, how to use it, how to adapt it to your data, how to check it, and how to take it away. Every result carries a confidence score, so you can see when it leaves the range the datasheet covers.

Conventions. Discharge current is positive. SOC is between 0 and 1. Temperatures are in °C in the interface and in K inside the equations. Resistances are shown in mΩ. Each page links here wherever a method needs explaining, and every figure below runs the same code as the tools.

Next: The cells: where the library comes from →

The cells: where the library comes from

Everything starts with a cell, so we start with the library.

The library contains reference cells, not measurements. Each entry combines a few per-cell quantities (capacity, mass, format, maximum continuous C-rate and a power-class factor) with chemistry-level parameters (OCV table, voltage window, resistance constant, time constant, Arrhenius coefficient and datasheet temperature range). Values are illustrative until an entry is validated against measurements.

R₀,25  = r_k · k / Q            r_k: chemistry constant [Ω·Ah], k: power-class factor, Q in Ah
R₁,25  = R₀,25 · r₁ᵣ            r₁ᵣ: chemistry ratio
E      = Q · V_nom / m · 1000   [Wh/kg], m in g
P      = E · C_max              [W/kg], at the maximum datasheet C-rate
hA     = 0.0053 · m^(2/3)       [W/K],  C_th = 0.9 · m [J/K]
envelope: C-rate in [0.2, C_max],  T in [T_min, T_max] (chemistry level)

A cell only enters the library if we know enough about it.

To add a cell as a validated entry, the datasheet (or your own test report) should give the items below. The right-hand column is how each one becomes a model parameter.

Extraction recipes

OCV(SOC)   from the lowest-rate curve: V_ocv = V(Q_d) + I · R_dc,   SOC = 1 − Q_d / Q
           then resampled to 101 points (1 % SOC step), the format of the library tables
R_dc       from two curves at equal discharged capacity (about 50 % DoD):
           R_dc ≈ (V_low − V_high) / (I_high − I_low)
B          from R_dc at two temperatures: B = ln(R_dc,1 / R_dc,2) / (1/T₁ − 1/T₂)    [K, T in kelvin]
Q_eff(T)   check the capacity at each temperature against the derating in the model

Limit. Discharge curves alone identify only the DC resistance R_dc = R₀ + ΣR_k. The split between R₀ and the RC branches needs pulse data, or the Calibrate page with a pulse profile. Until then the library uses the chemistry ratio r₁ᵣ. See calibration

Next: The cell at rest: open-circuit voltage →

The cell at rest: open-circuit voltage

Before any current flows, the cell has a voltage of its own.

With no current flowing, the terminal voltage settles to the open-circuit voltage (OCV), which depends only on the state of charge. Each chemistry defines it directly as a table of 101 points, one per 1 % of SOC. The simulators read it with a linear interpolation between neighbouring points, and the inverse (used to estimate an initial SOC from a rest voltage) is found by bisection.

OCV(s) = a_i + (a_{i+1} − a_i) · (100·s − i)       i = floor(100·s),  s in [0, 1]
a_0 … a_100  is the 101-point table of the chemistry (one value per 1 % SOC)
SOC₀ = OCV⁻¹(V_rest)                                  bisection, 30 steps

Next: The cell at work: equivalent circuits →

The cell at work: equivalent circuits

Now the cell starts working: current flows and the voltage moves.

All models share the same skeleton: an open-circuit voltage source, a series resistance R₀ and zero to three RC pairs that represent polarisation. Resistance only is the static model. 1RC, 2RC and 3RC are dynamic models.

SOC[k+1] = SOC[k] − I[k]·Δt / (3600 · Q_eff)            Q_eff = Q · SOH · f_T
f_T      = max(0.45, 1 − 0.008·(25 − T))  for T < 25 °C, else 1
k_T      = exp[B·(1/T_K − 1/298.15)] / SOH                  Arrhenius scale, resistance grows when cold or aged
R₀       = R₀,25 · k_T · g(SOC)                              see "Resistance vs SOC"
R_k      = R_k,25 · k_T
V_k[k+1] = V_k[k] + (I[k]·R_k − V_k[k]) · (1 − e^(−Δt/τ_k))    exact for a constant current over the step
V[k]     = OCV(SOC[k]) − I[k]·R₀ − Σ V_k[k]

The RC branches are split from the library R₁ and τ with fixed ratios, so the DC resistance R₀ + ΣR_k is identical across the dynamic models and only the time behaviour changes:

ModelBranch resistances (× R₁)Time constants (× τ)
Resistance onlynonenone
1RC11
2RC0.45 · 0.550.2 · 1.8
3RC0.30 · 0.40 · 0.300.1 · 0.9 · 7

After a calibration, the fitted branch values replace this split. Constant-current runs use a time step Δt = clamp(3600 / (C · 1500), 0.5, 20) s, profiles use 1 s. In power mode the current is I = P / V, solved with two fixed-point passes and limited to ±40 C. A run stops at V_min or SOC = 0 on discharge, and at V_max or SOC = 1 on charge (the constant-voltage phase is not modelled). The optional charge-transfer branch is explained in Charge-transfer resistance.

Next: Why resistance changes →

Why resistance changes

The first thing that moves is the series resistance, and it is not constant.

R₀ is not constant. It follows an Arrhenius law in temperature and rises at both ends of the SOC range, more strongly when the cell is nearly empty.

g(SOC) = 1 + 0.6·e^(−SOC/0.08) + 0.35·e^(−(1 − SOC)/0.03)
R₀(T, SOC, SOH) = R₀,25 · exp[B·(1/T_K − 1/298.15)] / SOH · g(SOC)

The rise near empty comes from slow solid-state diffusion and a falling exchange current. The smaller rise near full comes from a nearly saturated anode. The constants 0.6/0.08 (low SOC) and 0.35/0.03 (high SOC) give a realistic shape but are heuristics, not fitted to a dataset. They place the high-SOC rise above about 90 % SOC: about +1 % at 90 %, +7 % at 95 % and +35 % at 100 %.

Next: The fast branch: charge transfer →

The fast branch: charge transfer

Behind the first RC pair hides a surprise: its resistance depends on the current.

Principle

The charge-transfer step at the electrode follows the Butler–Volmer law: current grows exponentially with the overpotential η. For a symmetric reaction (α = 0.5) it reduces to a hyperbolic sine, with I₀ the exchange current.

I = 2·I₀·sinh(F·η / (2RT))      →      η = (2RT/F) · asinh(I / (2·I₀))
small signal:  R_ct,0 = RT / (F·I₀)      (a plain resistor, what a linear RC assumes)
large signal:  R_ct(I) = η / I = R_ct,0 · asinh(x) / x,     x = F·|I|·R_ct,0 / (2RT) = I / (2·I₀)
F = 96485 C/mol,  R = 8.314 J/(mol·K),  T in kelvin

Why it matters

A linear RC pair has the same resistance at every current. Real cells show a lower apparent resistance at high current: x = 1 gives 88 % of R_ct,0, x = 3 gives 61 % and x = 10 gives 30 %. Ignoring this over-predicts the voltage sag at high C-rates and makes fitted resistances depend on the amplitude of the test pulses.

In the tools

When the Rct option is on, the fastest RC branch becomes the charge-transfer branch: R₁(I, T) = R₁,25 · k_T · asinh(x) / x, and its time constant is τ_ct. It counts in the RC total: 1RC is Rct only, 2RC is Rct + 1 diffusion pair, 3RC is Rct + 2 diffusion pairs. The profile simulator uses the previous step’s current to evaluate x. The Compare page applies the same law to its resistance, R(t, SOC, I, T).

Fitting

R_ct,0 and τ_ct are fitted like any other branch (calibration). The current dependence is only identifiable if the profile contains several current amplitudes, so include pulses at different C-rates. α is fixed at 0.5, and I₀ follows from R_ct,0 and the temperature.

Next: The cell warms up →

The cell warms up

Current also heats the cell, and the heat changes everything above.

The cell is a single lumped thermal mass heated by I²R losses and cooled to the ambient temperature. The temperature feeds back into resistance and capacity, which is why a warm cell sags less than a cold one.

C_th · dT/dt = I² · (R₀ + Σ R_k) − hA · (T − T_amb)
C_th = 0.9 · m   [J/K, m in g]        hA = 0.0053 · m^(2/3)   [W/K]

Entropic heat, temperature gradients and changing airflow are not modelled. With a measured temperature, the Calibrate page can fit C_th and hA as multipliers on these library values, and the Compare page can cap the maximum power so that a pulse does not heat the cell above a temperature limit.

Next: How far to trust a result →

How far to trust a result

With all that in place, how much should you trust a number?

Inside and outside the datasheet

The model is evaluated directly at the requested C-rate, temperature and state of health. Inside the datasheet envelope the parameters apply. Outside, the result is an extrapolation: it is still computed, but flagged. Each condition adds a penalty, and the confidence is what remains.

e_C     = min(0.45, 0.3 · (C − C_max) / C_max)     if C > C_max
e_Clow  = 0.05                                      if C < 0.2   (single-cell simulator)
e_T     = min(0.4, 0.02 · (T_min − T))              if T < T_min
        = min(0.4, 0.025 · (T − T_max))             if T > T_max
e_SOH   = min(0.3, 0.9 · (0.95 − SOH))              if SOH < 0.95
confidence = max(0.1, 1 − Σe)
band       = ± (1 − confidence) · 0.25 V            drawn around the curve
dotted line wherever confidence < 0.9

The confidence is a heuristic, not a statistical interval. It tells you where to stop trusting the numbers, not how wrong they are.

Next: Putting it to work: scenarios →

Putting it to work: scenarios

To use the model you need a load: the scenarios.

A scenario is a repeating load profile, expressed as C-rate, current (A) or power (W). Positive values discharge, negative values charge.

constant   one level until a cut-off
pulse      30 s at the peak, then a rest of round(30·(peak/mean − 1)) s, so the average equals the mean
stair      steps from mean to peak, 300 s each, with 120 s rests
drive      40 segments of 30 s from a seeded generator (seed 11, reproducible):
           level x = 0.35 regeneration with probability 0.15, otherwise b^1.6, b uniform in [0,1]
           z = x / max(x),   level = k·(z − 1) + peak,   k = (peak − mean) / (1 − mean(z))
custom     CSV with a time column and one value column (current, C-rate or power);
           delimiter and header names are detected automatically;
           played once by default (raise Repetitions to loop it); tick “Charge current is positive”
           if the file uses that sign
power      I = P / V, with the voltage from the model

The drive cycle is synthetic. It is meant to show how cells react to a realistic mix of acceleration and regeneration, not to reproduce a standard cycle. The demo scenarios below are ready-made starting points; selecting one keeps the cells you chose. The simulator opens on Custom upload: drop a file, or pick a demo scenario or a built-in profile type.

Voltage limits per cell

By default each cell runs inside its datasheet voltage window. The Conditions card has a “Customise voltage limits” button that sets a window for each cell separately. Narrowing it simply ends the run earlier. Widening it past the datasheet is allowed within a cap per chemistry, because it can be physically meaningful (for example charging an NMC cell to 4.5 V instead of 4.2 V gives more capacity) but it is an extrapolation and it ages a real cell much faster.

window            V_min ≤ V ≤ V_max            default: the datasheet window of the cell
extra capacity    SOC_max = 1 + g_up · (V_max − V_ds,max)          SOC_min = − g_dn · (V_ds,min − V_min)
extended OCV      OCV(s > 1) = OCV(1) + (s − 1) / g_up             OCV(s < 0) = OCV(0) + s / g_dn
resistance        R₀ ← R₀ · (1 + 3·|s − clip(s, 0, 1)|)               impedance grows beyond the datasheet SOC range
confidence        − min(0.5, 1.5 · ΔV_outside)                       ΔV_outside: volts outside the datasheet window
life (rule)       cycle life ≈ 0.5^((V − V_ds,max) / 0.1 V)          shown in the results, illustrative only
ChemistryMax above datasheetMax below datasheetAbsolute floorg_up (SOC/V)g_dn (SOC/V)
NMC, NCA+0.30 V−0.30 V2.0 V0.500.25
LFP+0.15 V−0.30 V1.6 V0.250.15
LMFP+0.15 V−0.30 V1.6 V0.250.15
Na-ion+0.20 V−0.30 V1.2 V0.400.25
LTO+0.20 V−0.40 V1.0 V0.300.20
Li-metal+0.20 V−0.30 V2.5 V0.400.25

These caps and gains are heuristics chosen to stay physically reasonable: above the datasheet the electrolyte oxidises and the cathode degrades, below it copper can dissolve and damage the cell irreversibly. They are not measured values, so treat results outside the datasheet window as an exploration, not a prediction.

Next: Side by side: resistance and power →

Side by side: resistance and power

With a load defined, cells can be compared side by side.

For each cell the Compare page uses its library 3RC split. The resistance depends on time, SOC, current and temperature:

R(t, SOC, I, T) = R₀(T, SOC) + R_ct(I, T)·(1 − e^(−t/τ₁)) + Σ (k = 2, 3) R_k(T)·(1 − e^(−t/τ_k))
R_ct(I, T)       = R_ct,0(T) · asinh(x) / x                    (Butler–Volmer, see “The fast branch: charge transfer”)

t is the pulse length. A short pulse sees only the fast branches, a long pulse sees the full DC resistance. The maximum power is limited by the cut-off voltage on discharge and by the upper voltage on charge:

discharge:  V(I) = OCV − I·R(I);  find I_lim with V(I_lim) = V_min  (40 bisection steps)
            P_max = max over I in [0, I_lim] of I·V(I)               (40-point scan)
charge:     P_max = V_max · I_lim,   V(I_lim) = OCV + I_lim·R(I_lim) = V_max
optional temperature limit T_lim: the pulse of length t must not heat the cell above it,
            T_amb + I²·R(I)·(1 − e^(−t·hA/C_th)) / hA  ≤  T_lim        → current cap I_T (30 bisection steps)
            the power is then evaluated for I ≤ min(I_lim, I_T)

Without a temperature limit no current or thermal limits are applied, so the values are upper bounds. With one, R is evaluated at the ambient temperature (no heating feedback during the pulse) and the limit uses the cell’s lumped thermal parameters. See the charge-transfer branch for the current dependence.

Next: Making it yours: calibration →

Making it yours: calibration

Library values are a starting point. Your own measurements turn them into your model.

Calibration refits the library parameters so that the model reproduces your measured voltage. It works on one or several profiles at once.

  1. Load profiles. Each CSV has time, current, voltage and optionally temperature. Discharge current is positive (tick “Charge current is positive” on a profile to flip its sign). Up to six profiles; each is thinned to at most 6000/P points.
  2. Initial SOC. If left blank it is estimated as OCV⁻¹(V₀ + I₀·R₀), then refined as a fitted offset per profile.
  3. Parameters. You choose which to fit: R₀, the R and τ of every RC branch of the selected model, capacity, B, and the initial SOC of each profile. Each is a bounded multiplier of its library value. If a profile has a temperature column you can also fit the thermal model (C_th and hA).
  4. Predict. The same model as the simulator is integrated with the measured time steps and temperature.
  5. Minimise. A Nelder–Mead search, restarted four times with shrinking steps, minimises the voltage error pooled over all profiles (plus the temperature error when the thermal model is fitted).
  6. Report. RMSE before and after, per-profile errors, parameter changes, the equations used and the export.
  7. Check. Take the result to the Validate page and test it on profiles the fit has not seen. A glowing Validate card appears under the Fit card once a calibration has run.
p        = p_lib · exp(clip(a, −1.6, 1.6))              R₀, R_k, τ_k, Q  (× 0.2 … × 5)
B        = B_lib + 400 · clip(a, −3, 3)                 [K]
ΔSOC₀,j  = 0.05 · clip(a, −3, 3)                         one per profile, unless you enter it
RMSE_j   = sqrt( (1/N_j) · Σ (V_pred − V_meas)² )
J(θ)     = sqrt( (1/P) · Σ_j [ RMSE_j² + (λ·RMSE_T,j)² ] )       every profile has the same weight
           λ = 0.01 V/K; the temperature term only exists when the thermal model is fitted
C_th     = 0.9·m · exp(clip(a, −1.6, 1.6))       hA = hA_lib · exp(clip(a, −1.6, 1.6))      T_amb = first measured temperature
Nelder–Mead: steps 0.35, 0.15, 0.06, 0.02;  up to max(300, 70·n_params) iterations per stage

Charge-transfer branch

With Rct on, branch 1 uses the Butler–Volmer current dependence (details). With Resistance only selected there are no RC parameters to fit.

Thermal parameters

When a profile includes temperature, the library’s lumped thermal model (C_th = 0.9·m and hA) can be fitted as well. The model predicts the cell temperature from the current and the fitted resistances, and the temperature error enters the cost with a weight of 0.01 V/K. The ambient temperature is taken as the first measured temperature, so start profiles at thermal equilibrium.

Getting a good fit

  • Include pulses followed by rests, so the RC time constants show.
  • Use at least two current amplitudes if you fit Rct.
  • Vary the temperature across profiles if you fit B.
  • More branches fit better but are harder to identify: check the parameters, not only the RMSE.
  • The demo profiles are synthetic (2RC truth: R₀ ×1.4, RC resistances ×1.2–1.3, τ ×1.4–1.5, Q ×0.95, and a thermal truth with hA ×1.2 and C_th ×0.9): use them to see how the fit behaves.
  • The fit corrects the model for your profiles. Outside them it is still an extrapolation.

Next: Proving it: validation →

Proving it: validation

A good fit proves little until the model meets data it has never seen.

Calibration adjusts the parameters until the model reproduces the profiles it was given. A low error there does not prove the model is right: it may simply have learned those profiles. Validation tests it on up to three profiles that were not used for the fit.

  1. Choose the model. The one you just calibrated (a glowing Validate card appears under the Fit card on the Calibrate page and carries it over) or any library cell. For a calibrated model the library parameters are drawn too, so you see what the fit gained.
  2. Upload up to 3 profiles with time, current, voltage and, optionally, temperature. The initial SOC is estimated as OCV⁻¹(V₀ + I₀·R₀), which is only accurate if the profile starts from rest, unless you enter it. Each profile has a “Charge current is positive” checkbox.
  3. Run. Press “Run validation”: nothing is computed until you do. If you change an input afterwards the page asks you to run it again.
  4. Predict. The model is run on the measured current only. Voltage uses the measured temperature when you give it, otherwise the thermal model. If the temperature was measured, the thermal model is also run and compared with it (ambient = your setting, else the first measured temperature), with the calibrated thermal parameters if you fitted them and the library values otherwise.
  5. Analyse the errors: overall, by profile, by SOC and by C-rate, and against the calibration range.
  6. Export. The validated model can be exported for your BMS from the same page; the JSON also carries the validation errors.
e[k]    = V_pred[k] − V_meas[k]
bias    = mean(e)         RMSE = sqrt(mean(e²))         MAE = mean(|e|)
max     = max(|e|)        P95  = 95th percentile of |e|
R²      = 1 − Σ e² / Σ (V_meas − mean(V_meas))²
e_T[k]  = T_model[k] − T_meas[k],   C_th·dT/dt = I²·(R₀ + ΣR_k) − hA·(T − T_amb)
ratio   = RMSE_validation / RMSE_calibration
          below 1.5: generalises     1.5 to 3: use with caution     above 3: does not generalise

The ratio thresholds are rules of thumb. The page also warns when a validation profile leaves the range the calibration saw (temperature by more than 5 °C, or current by more than 20 %), because the error then includes extrapolation. The temperature error depends on cooling conditions the model cannot know: it uses the library’s lumped thermal parameters, so expect it to be larger than the voltage error.

Next: Taking it away: export →

Taking it away: export

Once the model is validated, it can leave the browser.

A calibrated model can be exported as JSON (all parameters including the thermal ones, the 101-point OCV table, validity range, fit error and, after a validation, the validation errors), a C header with an obf_step() function, a Python module with step(), or an R–T–SOC CSV table (−20 to 50 °C, 0 to 100 % SOC). The C and Python code carry every RC branch of the fitted model (the thermal parameters are in the JSON only). The same export is available on the Calibrate and Validate pages.

float v = obf_step(&state, I_A, T_C, dt_s);     // returns the terminal voltage and advances SOC and every V_k
                                                   // I_A > 0 is discharge

To check an integration, run the same current profile through the simulator and through your firmware and compare the voltages. The validity range in the JSON (the range of the calibration data) tells you the temperatures and currents the fit has seen.

Next: What to keep in mind →

What to keep in mind

Every model has edges. These are ours.

  • Library values are illustrative reference parameters, not manufacturer data.
  • Voltage limits widened past the datasheet extend capacity with heuristic gains and caps; they are an exploration, not a prediction of lifetime.
  • Voltage hysteresis, relaxation of the OCV and the constant-voltage charge phase are not modelled.
  • Ageing is a single state-of-health factor on capacity and resistance.
  • The thermal model is lumped (library values unless you calibrate C_th and hA); there is no thermal runaway or gradient.
  • Confidence is a heuristic flag, not a statistical interval.
  • A fit is only as good as its profiles; extra RC branches can fit noise.
